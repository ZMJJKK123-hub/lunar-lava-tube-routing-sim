# 自愈实验 —— 文件与数据字段大白话手册

## 这组实验在回答什么问题？

往网络里砸故障，掐表测三件事：

1. **自愈时间**：从出事到网络恢复，要几秒？（砸了六种故障各重复几遍）
2. **冗余度/鲁棒性曲线**：一次杀掉 3/6/12/18/24 个节点，网络还能恢复多少？
3. **链路恢复率**：干扰源压制期间断掉的链路，有多少能自己长回来？

## 文件说明

| 文件 | 一句话 |
|---|---|
| `healing_20260908_193940.md` | **★ 结论报告**：三张表看完（自愈秒表/杀节点曲线/恢复率） |
| `healing_20260908_193940.json` | 原始数据：每个场景一行（故障前覆盖率/谷底/恢复秒数/恢复期送达） |
| `run_healing.py` | 总控脚本：自动"重置→等稳→砸故障→掐表→下一场" |

## 复现

```bash
python -u report/自愈实验/run_healing.py     # 三实验全跑约 25 分钟
```

## 数据字段（json）

| 字段 | 大白话 |
|---|---|
| `exp1_heal_time[].scenario` | 故障类型（杀主干节点/塌方/随机杀/干扰源/竖切墙） |
| `exp1_heal_time[].heal_secs` | **从砸下故障到覆盖率恢复95%+脱离自愈模式的秒数**；null=150秒没救回来 |
| `exp1_heal_time[].min_cov` | 故障瞬间覆盖率跌到的谷底（墙切断=48.3% 最惨） |
| `exp1_heal_time[].log.投放道钉` | 恢复期间机器人投了几根钉（机器人参与自愈的证据） |
| `exp2_robustness[].k` | 这一场同时杀掉几个节点 |
| `exp2_robustness[].min_cov → final_cov` | 谷底覆盖率 → 120 秒后恢复到的覆盖率 |
| `exp2_robustness[].recovered_to_90` | 是否恢复到故障前 90%（冗余度判据） |
| `redundancy_max_k` | **冗余度结论**：仍能恢复 90% 的最大杀节点数 |
| `exp3_link_recovery[]` | 干扰源开 60 秒期间的断链/复链数，及召回后恢复率 |

## 结论速览（详见 md）

- 轻故障（杀单节点/塌方/干扰）自愈 **1~3.5 秒**；机器人救场时会自主投钉
- 竖切墙硬分区 150 秒不愈（声学呼救被墙挡死——设计边界，如实记录）
- **杀 18 个节点（30%）存活者仍 100% 重连**；24 个（41%）从 18% 拉回 60%（机器人补钉）
- 干扰源游走期间断链当场自愈，**召回时零积压**（链路恢复率 100%）

## 已知口径说明（诚实标注）

- 每场景用同一世界种子，故障目标确定性选取——是"确定性场景结果"而非统计平均
- 鲁棒性曲线每个 k 档只跑了 1 场（换种子多跑是后续改进项）
