# 道钉实验 —— RL 试点②「机器人学会什么时候该扔道钉」

## 这个实验在回答什么问题？

巡检机器人兜里只有 **6 根道钉**（钉子=预算，用一根少一根）。断网区域（孤岛）出现时，
把钉子插在能两头搭桥的位置就能救活它。但有个难题：

> **有的"孤岛"其实快自己恢复了**（节点会自动加大发射功率自救、干扰源走开链路就回来了），
> 钉子插上去就是白扔；有的孤岛是真断了，不插就永远救不回来。

- **A 组（规则版）**：机器人一到能搭桥的位置就**立刻插钉**，从不犹豫——老代码的行为
- **B 组（学习版）**：插钉前先"想一想"，从 **投 / 忍** 两个动作里选一个。怎么学会想？
  每次决定后 10 秒（40 拍）内**事后算账**：

| 决定 | 事后情况 | 奖惩 |
|---|---|---|
| 投了钉 | 断网节点**靠这根钉**连回来了 | **+1.0** 关键投资 |
| 投了钉 | 节点自己恢复了，钉子没人用 | **−1.0** 假孤岛，白扔 |
| 投了钉 | 10 秒后还是断的 | **−0.5** 无效投放 |
| 忍了等 | 等一等节点真自己恢复了 | **+0.5** 忍对了 |
| 忍了等 | 一直等到救援超时 | **−0.5** 忍晚了 |

机器人把决策时看到的 5 个迹象记成一张经验表（Q 表）：断多久了 / 那节点是不是正在
加大功率自救 / 周围还有几个活邻居 / 有没有干扰 / 兜里剩几根钉。同样的情况再见第二次
就查表挑历史上更划算的动作。一开始 35% 概率乱试（探索），随着经验积累逐渐按经验办事。

## 怎么跑的（方法学）

- 两组各跑 **3 轮 × 10 分钟**，同一张地图（种子 42），**灾害节拍完全相同**：
  每 60 秒一个灾害槽，轮换注入 炸主干节点 → 塌方 → 干扰源(开30秒) → 随机砸一个节点，
  逼出断网让机器人有活干。
- **A 组每轮重启**（无状态）；**B 组三轮共用一个服务器进程**、轮间只重置世界——
  Q 表跨轮保留，这是设计要点：道钉决策样本稀少，必须连续多轮才能看到学习曲线。
  （重置世界不弃表，手动关开关才弃表）
- **落钉审计两组同口径**：A 组虽然恒投，每根钉同样按上表算账——所以"白扔率"两组可比。

## 数据字段说明（单轮 json）

| 字段 | 大白话 |
|---|---|
| `summary.group` | 哪一组：`A-deploy-rule`=规则恒投 / `B-deploy-rl`=Q-learning |
| `summary.beacons_deployed` | 这轮机器人总共插了几根钉（全场结束时清点） |
| `summary.final_stock` | 收工时兜里剩几根（6 − 已插 − 审计在途） |
| `summary.coverage_integral_pct_s` | **覆盖率×时间积分**：整轮网络"健康面积"。越高=断网越少、恢复越快。这是"活干得好不好"的总分 |
| `summary.coverage_min_pct` | 灾害叠加瞬间网络最惨时的覆盖率（两组都跌到 ~20%，说明灾害烈度相同） |
| `summary.deploy_settled` | 学习器账本（已结算）：`good`=钉是关键投资 / `waste`=白扔 / `late`=投了没用 / `patient`=忍对了 / `hesitated`=忍晚了 |
| `summary.deploy_picks` | 决策计数：`invest`=选了投 / `wait`=选了忍 |
| `summary.deploy_epsilon` | 收工时探索率（还有几成概率在乱试） |
| `summary.waste_rate_pct` | 白扔率 = waste ÷ (good+waste)。**A 组也有此口径**（审计恒开） |
| `samples[]` | 每 5 秒一帧：覆盖率 / 模式 / 道钉累计数 / 兜里余量 / SOS 呼救中节点数 / 学习器瞬时状态 |
| `samples[].rl_picks / rl_settled` | 该时刻的决策与账本累计值——拼起来就是学习过程曲线 |

## 结论速览（详见 comparison_deploy.md）

- **省钉子**：B 组平均每轮插 **2.33 根** vs A 组 **3.67 根**——少用 36%
- **活一样好**：覆盖率积分 48005 vs 48204（差距 0.4%，在轮间波动 ±2400 之内）
- **账本干净**：B 组 10 次决定（5 投 5 忍），已结算 9 次全部正确：5 good + 4 patient，**0 白扔 0 错过**
  （剩下 1 次"忍"的终局在批次收尾时还没出结果，不计对错）
- 白扔率两组都是 0%——本轮灾害组合下"假孤岛"出现得少，学习器的"忍"没有白扔场景可学；
  干扰源占比更高的灾害组合更能考验这一点（后续实验方向）

## 诚实边界（如实标注）

1. **n=3 是小样本**：36% 的省钉率方向明确，但置信区间宽；跑 5~10 轮更稳
   （命令：`python -u report/道钉实验/run_deploy_ab.py 5 600 5001`，约 2 小时）
2. **学习还在早期**：探索率才从 0.35 降到 0.346（决策样本仅 10 次），离"收敛"很远；
   "越跑越会忍"的曲线需要更长批次才能显形
3. **巡逻偶遇不经审计**：机器人没接到任务、路过顺手搭桥的落钉（两组都有）不进账本——
   所以 `deploy_settled` 只统计"任务态"落钉，钉子总数则包含全部
4. **两组都 0 白扔**：不代表规则版不浪费，而是本轮灾害组合下白扔场景本就少；
   B 组的收益主要来自"忍对了 4 次"（省下的钉子留在兜里）

## 复现

```bash
# 完整批次 (3轮×2组×600s, 端口5001 与其他实验隔离):
python -u report/道钉实验/run_deploy_ab.py 3 600 5001
# 单场采集 (B组 300 秒):
python report/道钉实验/collect_deploy.py 300 --deploy-rl --port=5001
```

依赖：实验服务器由执行器自动在指定端口拉起（pythonw 隐身启动，避免与同机其他
批量实验的"孤儿清扫"冲突）；采集器对网络抖动装甲化（发送重试 + 停走看门狗 35s）。
